# 體驗課程電話預約紀錄網頁 - 客戶需求規格書

## 1. 專案概述
本專案旨在開發一個專為客服專員設計的「體驗課程電話預約紀錄網頁」。該網頁應具備良好的跨平台相容性（電腦與手機瀏覽器），協助專員在撥打電話給家長時，能夠高效、完整地記錄通話資訊，並確保所有必要的詢問與提醒事項皆已落實。

## 2. 使用情境
客服專員致電家長，協助其為孩子預約體驗課程。
- **預約成功**：完整記錄家長、學生、設備及預約課程資訊。
- **預約未完成**：仍需記錄通話聯繫紀錄及未成功原因。

## 3. 功能需求

### 3.1 跨平台操作
- 系統必須支援電腦與手機瀏覽器操作，具備響應式網頁設計（Responsive Web Design, RWD）。

### 3.2 參數化設定 (可擴充性)
- **輸入選項參數化**：所有下拉式選單、複選框的選項內容（如：課程名稱、年級、電腦類型等）不可寫死在程式碼中。
- **參數紀錄檔**：選項應儲存於一個獨立的參數紀錄檔（如 JSON 或 YAML 格式），方便管理人員日後人工修改。

### 3.3 彈性填寫流程
- **非線性輸入**：系統允許專員以「任意順序」填寫資訊，以配合通話中家長的對話節奏。
- **狀態提醒 (燈號機制)**：
    - 提供直觀的「燈號」或「進度標示」，提醒專員尚有哪些「必要詢問資訊」未填寫。
    - 提醒專員有哪些「必要告知事項」尚未勾選確認已提醒家長。

### 3.4 聯絡紀錄管理
- 無論預約是否完成，每一通電話都必須產生一條聯絡紀錄。
- 系統應能區分「僅聯絡待追蹤」與「正式預約成功」的狀態。

### 3.4 資料持久化與防失機制 (LocalStorage)
- **實時自動儲存**：專員在通話過程中所輸入或勾選的每一項資訊，皆須即時儲存於瀏覽器的 `LocalStorage` 中。
- **防止資料遺失**：若瀏覽器因意外關閉、崩潰或重新整理，當專員再次開啟網頁時，系統應自動載入先前已記錄之資訊，確保記錄不中斷且不遺失。

### 3.5 結案與清除紀錄
- **清除紀錄功能**：每通電話結束（結案）後，網頁應提供一個明顯的「清除通話紀錄」按鈕。
- **復原初始狀態**：點擊該按鈕後，應同時清除 `LocalStorage` 中的暫存資訊，並將網頁上所有輸入欄位與選項清空復原，以便進行下一通電話的紀錄。

## 4. 資料欄位定義 (參考實體關係設計)
根據 `erDesign.md`，系統應包含以下資訊維度：

### 4.1 家長資訊
- 主要聯絡電話
- 電子郵件
- 留單動機 (e.g., 家長想讓小朋友學、有興趣、舊生邀約、其他)
- 備註

### 4.2 學生資訊
- 姓名
- 年級 (e.g., 小班至高三、大學、其他)
- 稱謂 (家長與學生的關係)
- 學習程式經驗 (有/無)
- 學過的程式 (複選：麥塊、Scratch、Python、樂高、機器人等)
- 玩過遊戲經驗 (複選：麥塊、Roblox 等)
- 備註

### 4.3 設備資訊 (環境確認)
- 電腦類型 (筆電/桌電)
- 作業系統 (Windows/Mac)
- 網路類型 (Wi-Fi/手機熱點)
- 備註

### 4.4 預約課程資訊
- 課程名稱 (e.g., 麥思數學、艾伯特、麥塊、Roblox、Scratch、Python)
- 預約日期與時間
- 備註

## 5. UI/UX 設計原則
- **清晰引導**：針對「必須詢問」與「必須提醒」的事項，在 UI 上有醒目的區隔。
- **即時回饋**：填寫內容後，對應的燈號應立即變更狀態。
- **操作便捷**：針對手機操作，應使用適合點擊的大按鈕與選單。

## 6. 技術規範 (初步建議)
- **前端**：HTML5, JavaScript (Vanilla JS 或框架), CSS (具備 RWD)。
- **設定檔**：JSON 格式檔案。
