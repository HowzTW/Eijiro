# NaverMaps Memo 網頁應用設計需求

本文件詳細記錄了 「NaverMaps Memo」 網頁應用的視覺設計、互動流程與介面結構要求。

## 1. 核心設計原則
- **響應式設計 (Responsive Design)**: 網頁必須在手機（iOS/Android）與電腦（Desktop）瀏覽器上均有良好的瀏覽體驗。
- **視覺一致性**: 整體配色方案應與 `navermapsMemo/icon-solid.png` 協調，並以「視覺舒適」為前提進行搭配。

## 2. 應用程式圖標 (App Icons)
- **瀏覽器標籤頁 (Favicon)**: 使用 `navermapsMemo/icon-solid.png`。
- **iOS 主畫面圖標 (Apple Touch Icon)**: 使用 `navermapsMemo/icon-solid.png`。

## 3. 滿版封面/載入畫面 (Splash Screen)
網頁載入時，應先顯示一個滿版封面：
- **互動行為**: 
    - **自動消失**: 顯示一段時間後（或資料載入完成後）自動淡出消失。
    - **點擊消失**: 使用者點擊封面任何位置，封面應立即以淡出效果消失。
- **視覺呈現**:
    - **背景底色**: 與 `icon-solid.png` 的背景底色完全相同。
    - **中央區域**: 正中央顯示大型的 `icon.png`。
        - **動畫效果**: 具備「呼吸感」的脈動效果（Pulse Animation），縮放幅度為 `1.0` 至 `1.1` 倍。
    - **標題**: 圖標下方顯示醒目的應用名稱「NaverMaps Memo」。
    - **底部資訊**: 畫面最下方置中顯示小字「版本：yyyy-mm-dd hh:mi:ss」。
        - *註：日期與時間需自動讀取 `index.html` 檔案的最後修改時間（以台北時間為準）。*
- **互動行為**:
    - 封面顯示一段合適的時間（不宜過長）。
    - 隨後以「淡出 (Fade out)」效果消失，顯露出下方的主畫面。

## 4. 主畫面結構 (Main Interface)
主畫面主要分為兩大區塊：

### 4.1 頁首區塊 (Header Block)
- **定位**: 固定在畫面頂部 (Fixed/Sticky)，不隨頁面捲動而消失。
- **視覺**:
    - **底色**: 與 `icon-solid.png` 的背景底色相同。
    - **內容排列**: 
        - **Logo 與標題**: `icon.png` 與 應用名稱「NaverMaps Memo」水平排列且**無間距**。
            - **互動**: 點擊 Logo 圖示或標題可重新整理網頁。
        - **篩選按鈕**: 採**圓形按鈕**設計，**固定在畫面最右上角** (Position: Fixed)，僅顯示圖示 (Material Icon: `filter_alt`)。
            - 點擊後開啟「標籤篩選視窗 (Tag Block)」。


### 4.2 內容區塊 (Content Block)
- **內容**:
    - 以「小卡片 (Cards)」形式排列顯示景點資訊。
    - **排列規則**: 依據景點 `id` 進行**降冪排列** (Descending Order)，最新增的景點（ID 較大者）排列在最前面。
...
- **新增功能按鈕群 (FAB Group)**:
    - **位置**: 固定在主畫面右下角 (Fixed)。
    - **按鈕 1: 新增景點**: 圓形按鈕，包含新增圖示 (Material Icon: `add`) 與下方文字「新增景點」。
    - **按鈕 2: 管理標籤**: 位於「新增景點」按鈕之上。圓形按鈕，包含圖示 (Material Icon: `label`) 與下方文字「管理標籤」。
    - **樣式與功能**: 與此前的按鈕設計保持一致，點擊後分別開啟對應的視窗。
    - **小卡片版面配置**:
        1. 景點中文名稱
        2. 景點原文名稱
        3. `[在 Naver Maps 開啟]` 按鈕
        4. 標籤 (Tags): 依據 `tag_name`進行**正序排列** (A-Z)。緊接著標籤後方顯示一個連結型按鈕「設定標籤」。
            - **顏色**: 使用綠色，與「在 Naver Maps 開啟」按鈕調性一致。
        5. 景點簡介 (Description):
            - **文字格式**: 若原始資料包含分行符號，顯示時應予以保留並分行顯示，且每行之間應保留一小段底端間距 (Bottom-margin)。
            - **截斷顯示**: 若簡介超過 3 行，則自動截斷並顯示「展開」按鈕。
            - **展開與收合**: 
                - 點擊「展開」按鈕顯示全部內容，內容末尾顯示「收合」按鈕。
                - 點擊「收合」按鈕恢復 3 行顯示狀態。
            - **自動收合行為**:
                - **按壓其他卡片**: 點擊頁面上任何其他區域或卡片時，已展開的內容自動收合。
                - **捲動消失**: 當展開的卡片捲動出顯示範圍 (Viewport) 之外時，自動收合。
        6. 參考資訊連結
        7. 在「參考資訊連結」下方（若無連結則緊接著簡介後方），單獨一行顯示一個連結型按鈕「設定參考資訊」。
            - **樣式**: 字體與「設定標籤」連結按鈕一致。
            - **顏色**: 使用綠色，與「在 Naver Maps 開啟」按鈕調性一致。
            - **圖示**: Material Icon: `settings_ethernet`。
            - **互動**: 點擊後開啟「參考資訊設定 - (景點中文名稱)」視窗。
        8. **移除景點按鈕**: 
            - **位置**: 位於小卡右上角。
            - **樣式**: 連結型按鈕，包含圖示與文字。樣式與「設定標籤」一致。
            - **顏色**: 使用亮紅色。
            - **圖示**: Material Icon: `delete`。
            - **文字**: 「移除景點」。
            - **互動**: 點擊時彈出確認視窗，確認後進行連鎖刪除。
    - **參考資訊顯示邏輯**:
        - 以 `url_description` 作為超連結顯示文字。
        - 若 `url_description` 為空，則顯示完整的 `url` 字串作為超連結文字。
    - **圖標資源**: 網頁中所有圖標皆統一使用 [Google Material Icons (Material Symbols)](https://fonts.google.com/icons) 免費資源。
    - **資料來源**: 動態讀取自 Google Sheets。
        - **API URL**: `https://script.google.com/macros/s/AKfycbwbS7dJKnllCnZCcYWRogpeV5N8do80Dl4v7rigUA6q-7s0bkQsBkn24h_OZ4oF0dqt/exec`
        - **資料結構**: 參考 `navermapsMemo/setupDatabase.gs` 所定義的四個主要分頁：
            - `Attractions`: 景點主資訊。
            - `Tags`: 標籤定義。
            - `Attraction_Tags`: 景點與標籤的對照關係。
            - `Reference_URLs`: 景點的外部參考連結。
## 5. 彈出模組 (Modal)
### 5.1 標籤篩選視窗 (Tag Filtering Modal)
- **顯示方式**: 以懸浮視窗或彈出模組 (Modal) 呈現，包含半透明遮罩背景。
- **整體樣式**: 應與景點小卡有明顯區別感。
- **佈局配置 (由上而下)**:
    1. **標題與關閉**: 
        - 標題「標籤篩選」靠左排列。
        - **關閉按鈕**: 靠右排列的圓形按鈕，僅顯示「X」圖示，點擊取消並關閉視窗。
    2. **分隔線**: 置中之水平線。
    3. **批次操作**: 「全部選取」與「全部取消」以**連結形式**呈現，靠左排列。
    4. **標籤膠囊**: 置中排列所有標籤膠囊，且必須依據 `tag_name` 進行**正序排列** (A-Z)。
        - **選取狀態**: 實心填充深綠色背景並搭配霓虹綠文字（需符合指定參考圖）。
        - **未選取狀態**: 空心邊框且文字不發亮。
    5. **確定按鈕**: 位於最下方、靠右排列的圓形按鈕，僅顯示「勾選」圖示，點擊儲存選取狀態並關閉。
- **預設狀態**: 網頁載入時預設為「標籤全選」。
- **特殊篩選邏輯**:
    - **無標籤卡片**:
        - 當使用者「全選標籤」或「全部取消選取」時，顯示無標籤的卡片。
        - 當使用者「挑選特定標籤」時，隱藏無標籤的卡片，僅顯示符合所選標籤的內容。

### 5.2 新增景點視窗 (Add Attraction Modal)
- **顯示方式**: 以彈出模組 (Modal) 呈現，包含半透明遮罩背景。
- **介面欄位與必填標示**:
    - **景點中文名稱**: 必要，欄位旁顯示 `*` 或醒目必填標示。
    - **景點原文名稱**: 選填。
    - **NaverMap 網址**: 必要，欄位旁顯示 `*` 或醒目必填標示。
    - **景點簡介**: 選填，多行輸入。
- **即時驗證**: 
    - 當所有「必要欄位」尚未填寫完整時，「新增」按鈕為 **Disabled** 狀態。
    - 所有必要欄位填寫後，「新增」按鈕自動切換為 **Enabled**。
- **資料儲存邏輯 (Backend)**:
    - **ID 生成**: 提交資料時，以當下的 **Timestamp** 數值字串作為該景點的唯一 `id`。
    - **寫入資料庫**: 透過 GAS 的 `addAttraction` 函式將資料新增至 Google Sheets 的 `Attractions` 頁籤。
- **操作按鈕**:
    - **取消**: 關閉視窗，不保留輸入內容。
    - **新增**: 圖示化或清晰文字按鈕，點擊觸發資料寫入流程。

### 5.3 標籤設定視窗 (Tag Setting Modal)
- **顯示方式**: 以彈出模組 (Modal) 呈現，包含半透明遮罩背景。
- **佈局配置 (由上而下)**:
    1. **標題與關閉**: 
        - 標題「標籤設定 - (景點中文名稱)」靠左排列。
        - **關閉按鈕**: 靠右排列的圓形按鈕，僅顯示「X」圖示，點擊取消並關閉視窗。
    2. **分隔線**: 置中之水平線。
    3. **標籤膠囊群組**: 
        - 列出所有現有標籤為膠囊按鈕，且必須依據 `tag_name` 進行**正序排列** (A-Z)。
        - **初始狀態**: 與該景點目前已關聯的標籤狀態一致（選取者為實心、未選取者為空心）。
        - **互動**: 使用者點擊膠囊可 Toggle 選取狀態。
    4. **確定按鈕**: 位於最下方、靠右排列的圓形按鈕，僅顯示「勾選」圖示。
        - **功能**: 
            - 批次更新該景點與標籤的關聯關係 (Attraction_Tags 資料表)。
            - 關閉視窗。
            - 即時刷新主畫面該景點小卡的標籤顯示（需維持排序）。

### 5.4 標籤管理視窗 (Tag Management Modal)
- **顯示方式**: 以彈出模組 (Modal) 呈現，包含半透明遮罩背景。
- **功能要求**:
    1. **標籤清單**: 列出所有現有標籤，依 A-Z 排序。每個標籤旁邊顯示「修改」與「刪除」圖示。
    2. **修改標籤名稱 (Rename)**:
        - **視覺引導**: 標籤名稱區域應具備適當視覺反饋（如：虛線底線、懸停變色），引導使用者發現該欄位可編輯。
        - **驗證**: 新名稱不能有空白，且不可與其他現有標籤名重複 (Unique)。
        - **儲存**: 更新 `Tags` 表中的 `tag_name`。
    3. **新增標籤 (Create)**:
        - 提供專屬輸入框與「+」按鈕。
        - **介面配置**: 位於視窗底部，與標籤列表區塊分離。標籤列表應具備獨立捲軸，捲動時不應穿透或與新增區域重疊。
        - **防重現提交**: 點擊「+」後應立即清空輸入框並禁用按鈕，防止快速重複點擊導致資料重複。
        - **驗證**: 不得填入空白字元，名稱必須不重複。
        - **自動選取邏輯**: 新增標籤後，若當前標籤篩選狀態為「全部選取」，則新標籤應自動加入已選取名單（維持全選狀態）。
    4. **刪除標籤 (Delete)**:
        - **關連檢查**: 刪除前必須列出所有目前正使用此標籤的「景點中文名稱」。
        - **確認行為**: 彈出視窗詢問：「此標籤目前與以下景點關聯：(景點名稱清單)，確定要刪除嗎？」
        - **連鎖刪除**: 確認後，除了刪除 `Tags` 表中的該標籤外，也必須一併從 `Attraction_Tags` 中移除所有相關的關聯紀錄。
 
 ### 5.5 參考資訊設定視窗 (Reference URL Setting Modal)
 - **顯示方式**: 以彈出模組 (Modal) 呈現，包含半透明遮罩背景。
 - **佈局配置**:
     1. **標題與關閉**: 
         - 標題「參考資訊設定 - (景點中文名稱)」靠左排列。
         - **關閉按鈕**: 靠右排列的圓形按鈕，僅顯示「X」圖示。
     2. **分隔線**: 置中之水平線。
     3. **URL 清單 (列表形式)**: 
         - 列出該景點目前已有的所有參考資訊。
         - 每一項顯示 `url_description`（若無則顯示 `url`）。
         - 每項右側各有一個「刪除」按鈕（圖示：`delete`）。
     4. **新增區域 (位於底部)**:
         - 提供兩個輸入框：`網址說明` 與 `網址`。
         - 提供一個「+」按鈕。
         - **驗證**: 「網址」為必填，不得為空白。點擊「+」後新增一筆紀錄並清空輸入框。
 - **資料儲存邏輯**:
     - 新增與刪除操作應立即反映在前端 (Optimistic UI)。
     - 透過 GAS 進行背景非同步儲存至 `Reference_URLs` 資料表。
